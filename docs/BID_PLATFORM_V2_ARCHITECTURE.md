# Bid Agent 完整投标文件平台升级架构

## 1. 产品目标

系统从“生成技术方案章节”增量升级为“按招标格式编制完整投标文件”。
任何自动生成都必须同时满足：格式可保真、事实可核验、来源可追溯、材料有权限、目录经人工确认。

## 2. 固定主链路

```text
项目上传
  → 文件有效性与隐私处理
  → 投标文件格式识别（最多五级）
  → 响应事项与采分点分析
  → 响应策略与风险判断
  → 项目变量缺口识别
  → 企业资料权限过滤
  → 业绩/人员/资质/历史案例匹配
  → 完整目录与材料清单规划
  → 人工确认目录、变量和材料
  → 按章节生成或按原表回填
  → 逐章采分点与事实校核
  → 企业制度审批门禁
  → 整本交付审核
  → 保真 Word 导出
```

各阶段只能读写明确的数据契约，不允许 Agent 自由循环，也不允许后续模块绕过权限和人工门禁。

## 3. 模块边界

| 模块 | 输入 | 输出 | 禁止行为 |
|---|---|---|---|
| Template Analyzer | 原始 PDF/DOCX | 模板起点、五级标题、表格、固定字段、严格性 | 根据经验改写招标模板 |
| Requirement Engine | 原文、抽取规则 | 细粒度响应事项与来源坐标 | 把目录标题当作完整要求 |
| Scoring Engine | 评分办法 | 采分条件、数量、上限、证据要求 | 自行宣布得分 |
| Project Variable Center | 模板字段、企业资料 | 已核验变量、缺失变量、项目内引用 | 猜测授权代表、身份证号等 |
| Material Matcher | 采分条件、台账、资料索引 | 候选材料、匹配原因、冗余建议 | 绕过机构/项目权限 |
| Permission & Approval | 用户、机构、材料用途 | 可读、可下载、可插入、待审批 | 用“检索到”代替“获准使用” |
| Proposal Planner | 模板目录、响应策略、采分点 | 完整目录、章节任务、材料插槽 | 让商务/资格条款误入技术正文 |
| Chapter Writer | 规则、要求、核验知识、案例结构 | 受字数约束的章节草稿 | 复制旧项目事实或编造企业事实 |
| Evidence Assembler | 原模板、扫描件、核验字段 | 表格回填、图片装配、附件清单 | 改变原表结构 |
| Review & Delivery Gate | 正文、材料、来源、采分点 | 覆盖率、缺口、风险、审批状态 | 用无依据的“AI判断”替代证据 |

## 4. 核心数据对象

### Template Outline Node

- title、level（1-5）、sort_order
- parent、source_location、original_style
- node_type：fixed_text/table/form/generated_section/attachment_slot
- editable、required、strict_fidelity

### Scoring Point

- 原文、页码、评分上限、单项分值
- 条件表达式、数量规则、去重规则
- 所需正文、所需材料、预计满足状态

### Project Variable

- 变量名称、值、来源、核验状态
- 适用项目、敏感等级、允许用途
- 关联材料与最后修改人

### Material Candidate

- 材料类型、机构归属、持有人/合同编号
- 匹配条件、有效期、证据位置
- 可读/可下载/可插入权限和审批状态

## 5. 业务规则

1. 招标文件格式详细：章节标题、固定文字和表格原样保留。
2. 格式简略或缺失：仅补充缺失结构，历史案例只提供结构和表达参考。
3. 商务偏离默认可建议“无偏离”，但必须人工确认后写入。
4. 业绩匹配按业务类型、客户属性、时间等逐级筛选，并建议多准备 2-3 项。
5. 人员证书按证书类别、社保单位、一人一分规则检查，并建议多准备 1-2 人。
6. 未核验变量一律留空并集中提示，不阻塞其他无关章节。
7. 章节生成必须有可配置字数上下限和用户定制要求。
8. 合同全页等受控材料必须在审批通过后才允许装配和导出。

## 6. 分阶段验收清单

| 阶段 | 可独立验收的结果 | 当前状态 |
|---|---|---|
| A | 自动检测原文模板并展示最多五级标题 | 本地完成 |
| B | 目录节点可增删、改名、排序、设父级，保存前人工确认 | 待数据迁移 |
| C | 每章支持定制要求、字数上下限、案例参考策略 | 本地完成 |
| D | 项目变量集中发现、核验、项目内复用 | 项目内档案完成；跨项目复用待迁移 |
| E | 评分点拆解、材料条件和正文覆盖检查 | 部分已有 |
| F | 业绩和人员证书候选匹配、去重计分、冗余建议 | 待真实台账 |
| G | 钉钉目录权限过滤、下载与材料装配 | 待接口文档与授权 |
| H | 审批流、整本审核、原模板 Word 交付 | 部分已有 |

当前“人工事项档案”从既有项目数据实时汇总变量、格式、材料、章节和冲突任务。
它不复制敏感值，也不创建跨项目人员档案；变量填写后保存在当前 Workspace 的模板档案中，后续生成和导出统一读取。

## 7. 外部依赖

- 钉钉开放平台接口文档、应用身份和测试租户。
- 可开放文件夹清单及查看/下载权限矩阵。
- 项目合同台账字段字典、人员与社保单位关联规则。
- 合同全页等敏感材料的审批人、审批时效和失败处理规则。
- 业务人员提供至少 3 组“评分办法 → 最终采用材料 → 中标响应”标注案例。
