# Bid Agent MVP 实施路线图

## 总体策略

每个阶段都形成可演示、可测试的增量。只有代码、配置、迁移、接口、错误处理和相应测试都通过，阶段才算完成。

## 阶段 0：现状审计与安全基线

目标：知道现有代码能做什么，清理不应进入 Git 的文件和敏感信息。

交付：

- 代码、依赖、容器、数据库、前端和 ECS 现状清单。
- 干净的仓库基线。
- 历史泄漏处置方案。

完成标准：

- 本地基线不跟踪 `.env`、虚拟环境、缓存、构建产物和真实招标文件。
- Git 可达历史不包含已知敏感值。
- 已暴露的外部密钥完成吊销与换新。

当前状态：本地基线已完成；远端历史替换和外部密钥吊销仍待最终完成。

## 阶段 1：产品与架构定稿

目标：锁定最短闭环，避免边做边扩大范围。

交付：

- `MVP_SPEC.md`
- `ARCHITECTURE.md`
- `API.md`
- `ROADMAP.md`

完成标准：

- 产品范围、状态、数据模型和接口相互一致。
- 明确 PDF 与 DOCX 的来源定位差异。
- 每个后续阶段都有独立验收口径。

## 阶段 2：Foundation

目标：建立可持久化的项目骨架。

交付：

- 项目、文件、任务等基础模型。
- 正式数据库迁移机制。
- 项目创建与查询接口。
- 统一错误响应、配置校验和健康检查。

完成标准：

- 全新数据库可一键迁移。
- 项目创建后重启服务仍可读取。
- 配置缺失时安全失败，日志不泄露敏感值。
- API、迁移和 Docker 冒烟测试通过。

## 阶段 3：真实上传与 Parser

目标：用真实 PDF/DOCX 产生可追溯来源片段。

交付：

- 安全上传与受控文件存储。
- PDF 分页解析。
- DOCX 分段解析。
- 解析任务、错误记录和重试。

完成标准：

- PDF 片段保留正确页码。
- DOCX 片段保留正确段落范围。
- 损坏、加密、空白、过大和扫描文件得到明确错误。
- 重复上传和重试不会产生混乱数据。

## 阶段 4：Requirement Engine

目标：提取、展示并人工确认要求。

交付：

- 候选要求提取。
- 分类、去重、置信度和来源引用。
- 要求编辑、确认和软删除接口。
- 前端要求确认页。

完成标准：

- 真实样例至少提取 5 条可核对要求。
- 每条已确认要求至少有一个有效来源。
- 用户可以打开原文、修改并确认。
- 模型失败可重试，中间结果不丢失。

## 阶段 5：Writer

目标：基于已确认要求生成并编辑一个章节。

交付：

- 章节与要求关联。
- 单章节生成。
- 事实边界提示和自动校核。
- 章节版本与网页编辑。

完成标准：

- 只能选择当前项目已确认要求。
- 生成内容记录输入快照和要求映射。
- 无依据事实不会被写成确定承诺。
- 编辑保存、版本冲突和失败重试测试通过。

## 阶段 6：Export

目标：把已确认章节导出为可用 DOCX。

交付：

- DOCX 模板和渲染器。
- 导出记录、下载接口和错误处理。
- 内容与要求响应清单。

完成标准：

- 导出文件可由 Word 正常打开。
- 标题、正文、分页和响应清单可读。
- 下载不暴露服务器路径。
- 同一版本可重复导出。

## 阶段 7：前端闭环联调

目标：非技术用户能在一个界面完成全流程。

交付：

- 项目列表和新建项目。
- 上传与处理进度。
- 要求确认。
- 单章节生成、编辑和导出。
- 统一空状态、加载状态和错误提示。

完成标准：

- 不借助命令行完成 MVP 闭环。
- 刷新页面后状态一致。
- 所有按钮连接真实 API，不以模拟数据假装成功。
- 桌面主流程可用并完成基本响应式检查。

## 阶段 8：真实样例验收

目标：用真实招标文件验证质量和恢复能力。

交付：

- 脱敏验收记录。
- 要求溯源准确率抽查。
- 章节质量问题清单。
- 性能与失败恢复记录。

完成标准：

- 满足 `MVP_SPEC.md` 十项验收标准。
- 已知问题有明确级别和后续安排。
- 不在 Git 或日志保存真实敏感材料。

## 阶段 9：ECS 部署与交付

目标：在 `/opt/bid-agent` 完成可重复部署。

交付：

- 经验证的 Docker Compose。
- 数据库迁移、健康检查和持久卷。
- 部署、备份、回滚说明。
- ECS 集成测试结果。

完成标准：

- 从干净环境可按说明启动。
- Web、API、任务、数据库和存储健康。
- 数据重启不丢失。
- 端口、凭据和日志符合安全边界。
- 回滚演练成功。
